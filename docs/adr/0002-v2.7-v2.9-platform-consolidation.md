# 0002. Konsolidacja Architektury: Ewolucja w Platformę Orkiestracji Zadań i Agentów (v2.7 – v2.9)

* **Status:** Zaakceptowana
* **Data:** 2026-09-08
* **Autorzy:** Kacper Czeczot / Antigravity AI

---

## 1. Kontekst i Problem

Wersje v2.0–v2.6.1 Antigravity Mesh udowodniły dojrzałość warstwy I/O: strumieniowanie plików, podgląd dokumentów biurowych, PDF, audio, wideo, kodowanie składni, instalator APK oraz samoleczenie uprawnień i zarządzanie energią (Zero-Sleep / IOKit).

Jednak dotychczasowa architektura opierała się na modelu **„Endpoint Soup”** — dużej liczbie płaskich, synchronicznych endpointów HTTP (`/query`, `/read-file`, `/upload`, `/exec`, `/ask`). Model ten napotyka na bariery skalowalności:
1. **Brak deklaratywności węzłów (Capability Model)**: Klient (Android / CLI) musi zgadywać możliwości danej maszyny na podstawie platformy operacyjnej.
2. **Kruchość synchronicznego wykonywania poleceń (`/exec`, `/ask`)**: Długotrwałe kompilacje lub testy są podatne na zerwania połączeń mobilnych (np. przełączenie Wi-Fi -> LTE).
3. **Płaski model uprawnień (All-or-Nothing Token)**: Posiadanie tokena PSK daje nieograniczony dostęp do powłoki shell bez polityk bezpieczeństwa (Execution Policies).
4. **Rozdrobnienie planu wydań**: Pierwotny plan zakładał aż 8 drobnych wersji ze skokami major (v2.7–v4.0), co groziło przeciążeniem wydań (release fatigue) i chaosem w numeracji.

---

## 2. Podjęta Decyzja: Konsolidacja do 3 Spójnych Wydań Minor (v2.7 ➔ v2.8 ➔ v2.9)

Zamiast rozpraszać prace na 8 wersji ze skokami wersji major, konsolidujemy plan rozwoju do **3 spójnych, kolejnych wydań minor w linii v2.x**, gwarantując pełną wsteczną zgodność:

```
v2.6.1 (Stable) ────► v2.7: Foundation & Task Engine ────► v2.8: Cluster & Project Workspace ────► v2.9: Autonomous Agent Mesh
 [Bieżące I/O,         - Capability Model (GET /api/v1/node)   - Cluster Fan-Out & Scheduler           - Agent Profiles & Delegation
  Power Mgmt]          - Asynchroniczny Task Engine            - Pierwszoklasowy obiekt "Project"      - Device Bridge (Clipboard, Push)
                       - Execution Policies (Safe/Normal)      - Natywna integracja z Git              - WebRTC Screen/Audio Bridge
                       - Baza stanu & Wsteczna zgodność        - mTLS & Tożsamość urządzeń
                       - Android Task Center                   - Agent Workspace w Androidzie
```

---

## 3. Szczegółowy Zakres Wydań

### 🎯 Kamień Milowy 1: Wydanie `v2.7` — Foundation & Task Engine
*Cel: Przekształcenie węzła z synchronicznego serwera RPC w odporną na zerwania platformę zadań.*

1. **Model Możliwości (Capability Model)**:
   - Nowy endpoint kontraktowy: `GET /api/v1/node` zwracający deklarację sprzętowo-programową:
     ```json
     {
       "node_id": "mac-studio-01",
       "name": "Mac Studio",
       "platform": "macos",
       "arch": "arm64",
       "capabilities": {
         "filesystem": true,
         "process_exec": true,
         "agent": true,
         "agent_stream": true,
         "gpu": true,
         "tcc_audit": true,
         "tasks": true
       }
     }
     ```
   - Dynamiczne dostosowywanie interfejsu w aplikacji Android na podstawie możliwości węzła.
2. **Asynchroniczny Silnik Zadań (Task Engine)**:
   - Endpointy: `POST /api/v1/tasks`, `GET /api/v1/tasks`, `GET /api/v1/tasks/:id`, `DELETE /api/v1/tasks/:id`.
   - Maszyna stanów zadania: `QUEUED` -> `RUNNING` -> `COMPLETED` / `FAILED` / `CANCELLED`.
   - Odporność na rozłączenia: zadanie uruchomione z telefonu wykonuje się w tle na serwerze; logi i artefakty czekają na odbiór.
3. **Polityki Wykonawcze i Bezpieczeństwo (Execution Policy)**:
   - Tryby: `SAFE` (whitelist dozwolonych narzędzi: git, cargo, npm, gradle, python), `NORMAL` (z blokadą destrukcyjnych komend: rm, shutdown, format), `UNRESTRICTED`.
4. **Lokalny Stan Trwały i Event Bus**:
   - Wbudowana lekka baza w Rust (`redb` / statyczny SQLite) przechowująca historię zadań, logi zdarzeń i tokeny.
   - Ujednolicony strumień zdarzeń SSE `/api/v1/events` (`task.*`, `node.*`, `process.*`).
5. **Wsteczna Kompatybilność**:
   - Zachowanie pełnej zgodności ze starymi endpointami v2.6.x (`/health`, `/system`, `/query`, `/read-file`, `/ask/stream`).
6. **Aplikacja Android**:
   - Nowe centrum zadań (*Task Center*) prezentujące trwające i ukończone zadania na węzłach klastra.

---

### 🚀 Kamień Milowy 2: Wydanie `v2.8` — Multi-Node Cluster Orchestrator & Project Workspace
*Cel: Połączenie maszyn w spójny klaster z orkiestracją zadań, kontekstem projektowym i natywnym Git.*

1. **Inteligentny Scheduler i Fan-Out Zadań**:
   - Rozpraszanie zadań na wiele maszyn naraz (np. kompilacja i testy równolegle na Macu, PC i Linuksie).
   - Dobieranie maszyn według kryteriów zadania (`needs: macOS + ARM64` lub `needs: CUDA >= 12.0`).
2. **Obiekt Pierwszoklasowy: `Project`**:
   - Zastąpienie surowych ścieżek dyskowych bytem projektu (nazwa, repozytorium, workspace, profile build/test).
3. **Natywna Integracja z Git**:
   - Endpointy: `/api/v1/git/status`, `/api/v1/git/diff`, `/api/v1/git/branches` zwracające czyste struktury JSON bez konieczności parsowania tekstu powłoki przez agenta.
4. **Bezpieczeństwo Klasy Enterprise (mTLS & Granular RBAC)**:
   - Tożsamość kryptograficzna maszyn i telefonów z automatyczną wymianą certyfikatów przy parowaniu PIN.
   - Uprawnienia per-capability (`filesystem.read` vs `process.execute`).
5. **Ewolucja Czatu w `Agent Workspace`**:
   - Przebudowa ekranu czatu w Androidzie na pełnoprawny pulpit projektu z podglądem gałęzi Git, kafelkiem zadania i blokami myślenia agenta.

---

### 🌐 Kamień Milowy 3: Wydanie `v2.9` — Autonomous Agent Mesh & Device Bridge
*Cel: Pełna autonomia agentów i głęboka integracja peryferiów pomiędzy urządzeniami.*

1. **Profile Agentów i Delegacja Międzywęzłowa (Agent-to-Agent)**:
   - Autonomiczne delegowanie podzadań przez agenta na Macu do agenta na stacji roboczej Windows.
   - Profile ról: *Developer*, *Tester*, *Reviewer*, *DevOps*.
2. **Most Urządzeń (Device Bridge)**:
   - Obustronny schowek systemowy w czasie rzeczywistym (Clipboard Sync).
   - Przekazywanie powiadomień systemowych między komputerem a telefonem.
   - Opcjonalny podgląd ekranu pulpitu przez WebRTC.

---

## 4. Konsekwencje i Korzyści

* **Pozytywne:**
  - Redukcja liczby wydań z 8 do 3 zwartych faz eliminuje chaos i przyspiesza dostarczenie wartości użytkowej.
  - Wersja `v2.7` natychmiast rozwiązuje problem rozłączania zadań mobilnych i standaryzuje API.
  - Zero regresji: zachowanie 100% wstecznej kompatybilności dla aplikacji Android v2.6.1.
  - Projekt zyskuje unikalną pozycję rynkową jako prywatna platforma orkiestracji AI nad własnym sprzętem.
* **Kompromisy:**
  - Wydanie `v2.7` wymaga dodania lekkiej warstwy bazy stanu (wybór `redb` w Rust eliminuje zależności C).
  - Konieczność równoległego wspierania API legacy oraz `/api/v1/` w okresie przejściowym.
